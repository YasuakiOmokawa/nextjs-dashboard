# src

- SPA が呼ぶ API は `spa-contract.ts` の契約に endpoint (path・params・payload・success・error) を足し、`spa-http-api.ts` の `handlers` の表に handler を書く。表の型 `DecodedHandlers` が、宣言していない失敗を返すこと、引数の `request` を読むこと、handler の書き漏らしを型エラーにする。応答は契約の success の schema で encode され、schema に無い項目は送られない。payload の schema には JSON の形 (string・number・boolean・配列) と要求の大きさの上限 (配列の件数など) だけを書き、id の形やレベルの範囲などの値の意味は Service が decode して tagged error にする。形が違えば HttpApi の decode が本文の無い 400 を返す。
- 契約の endpoint は `app.ts` が `HttpApi.reflect` で Hono に登録し、要求ごとに session を 1 回確かめて結果を契約の middleware (`Authenticated`) に渡す。認証は `SpaApi` の全 group に掛かり、`.middleware(Authenticated)` より後に `.add` した group には掛からず、そう足した group は `__tests__/app.test.ts` の契約の列挙のテストで失敗する。session を見ない公開の route は `app.ts` の Hono に足し、`app.test.ts` の `PUBLIC_ENDPOINTS` に method と path を書く。Worker が受けるのは `wrangler.jsonc` の `run_worker_first` に当たる path だけで、外れた path は Static Assets が `index.html` を返す。どれも、`app.test.ts` の全ての route を列挙するテストが守らないと失敗する。
- SPA の `/dashboard/<page>` の画面が最初に呼ぶ API は `/api/<page>` に置く (`/dashboard` は `/api/teams`)。`web/index.html` の inline script がこの対応で、JS の読み込みを待たずに `/api/me` と画面の API を呼び始め、画面の atom の取得が通る fetch (`web/src/api.ts` の `fetchWithinSession`) が同じ path の最初の GET にその応答を使う。対応から外れると要求が 1 本無駄になり、`web/src/__tests__/router.test.ts` が落ちる。
- SPA (`web/src`) が import できる repo 内の module は、契約 (`spa-contract.ts`) と、契約が読む `db/ids.ts`・`db/column-values.ts` だけで、それ以外を import すると `.fallowrc.json` の `boundaries` が lint のエラーにする。契約は server の module を型だけ import できる。
