# src/services

- Effect の中から DB と外部 API/SDK は Service 越しに触る。Service は `Db` (drizzle) を直接使い、Repository 層は作らない。Service の書き方は `node_modules/effect/AGENTS.md` に従う。
- Service は `index.ts` の `runServiceWithoutDb`・`runReadService`・`runScopedService`・`runManagerScopedService` だけが走らせる。session は Worker の middleware (`src/app.ts`) が作り、`CompanyContext`・`AuthorizationContext`・`CompanyMembers` (session と同じ guard で taimei-auth に一覧を問い合わせる)・`CompanyTeamList` (事業所の DO に写したチーム一覧) を持つ。どの実行口もこれらを request ごとに provide する。`runScopedService` と `runManagerScopedService` は加えて RLS の事業所を設定した transaction (`db/scoped.ts` の `withCompanyScope`) の `Db` を provide し、本体が失敗したら transaction を戻す (理由は `docs/adr/0005-row-level-security.md`)。SQL を流さない本体は `runServiceWithoutDb` で走らせ、transaction を開かない (本体が `Db` を要求すると型エラー)。画面の読み取りは `team-reads.ts` の `TeamReads` に置く。一覧 (`listTeams`) は事業所の DO の表 (`CompanyTeamList`) から読み、DO が空なら DB の関数 `company_team_list` を呼ぶ 1 つの SQL 文で読んで DO に置く (関数の書き方は `db/CLAUDE.md`)。見える範囲は要求ごとに `TeamReads` が `team_visible_to` と同じ規則で絞る。星取表 (`getTeam`) は DB の関数 `team_matrix` を 1 文読む。一覧を変える書き込みは `TeamManagement` だけにあるので、`runManagerScopedService` が本体の成功の後に同じ transaction で版を増やし、commit の後、応答の前に DO の一覧を書き直す (commit したか分からない `DbUnavailable` では消す)。`runScopedService` (メンバーのレベルの保存) は DO を触らない (理由は `docs/adr/0008-company-teams-cache.md`)。`runReadService` が transaction を開かずに走らせ、本体が要求できるのは `TeamReads` と要求ごとの Service だけ (書き込みの Service と `Db` は型エラー)。`TeamReads` は `runScopedService` では要求できない。API の handler の書き方は `src/CLAUDE.md`。
- Service に失敗の型を足したら `team-errors.ts` の `TeamFailure` に入れ、`src/lib/team-failure.ts` の表に文言・状態コード・報告するかどうかを書く (書くまで型エラーになる)。
- 管理者だけの操作は `TeamManagement` に置き、method で role を見ない。`TeamManagement` は `runManagerScopedService` で走らせる。この実行口は、管理者でない session を transaction を開く前に `NotManager` で返し、管理者には要求ごとに `TeamManagement.layer` を組み立てて provide する (layer の組み立ても、管理者でなければ `NotManager` で失敗する)。`runScopedService` の本体は `TeamManagement` を、`runManagerScopedService` の本体は `TeamService` を要求できない (型エラー)。
- 事業所データを読む Service は method 内で `CompanyContext` を `yield*` する。理由は `docs/adr/0002-company-data-scoping.md`。
- レベルを記入する人のチームへの割り当て、記入するスキルがそのチームにあること、名前の一意は、事前の query で確かめない。`team-service.ts` の `runWrite` で savepoint の中で書き、制約の違反を tagged error に写す (制約の名前は `db/drizzle/schema.ts` の定数)。レベルを 1 つも送らない保存だけは書き込みが無いので、割り当てを読んで確かめる。
